| Layer              | Chosen                                    | Alternatives Considered                                         | Why Chosen                                                                                                                                                                                                                                |
| ------------------ | ----------------------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Desktop shell      | **Electron**                              | Tauri                                                           | Team already committed to Electron; larger ecosystem for FFmpeg child-process integration and native module support; Tauri's smaller binary/memory footprint is a future optimization candidate, not an MVP blocker.                      |
| Frontend framework | **React 19 + TypeScript**                 | Vue, Svelte                                                     | Team preference; largest ecosystem for the UI libraries needed (Recharts-style progress viz, shadcn/ui, Framer Motion); TypeScript for type safety across IPC contract boundaries.                                                        |
| Build tool         | **Vite**                                  | Webpack                                                         | Faster dev server / HMR, simpler config, standard pairing with Electron + React in 2026.                                                                                                                                                  |
| Styling            | **Tailwind CSS v4**                       | CSS Modules, styled-components                                  | Utility-first speeds up building consistent, dense UI (file lists, rule builders) without heavy custom CSS; pairs directly with shadcn/ui.                                                                                                |
| Component base     | **shadcn/ui**                             | MUI, Ant Design                                                 | Unstyled/composable primitives that avoid the "generic Material Design" look reviewers criticize in dated competitor UIs (Bulk Rename Utility, File Juggler); full control over theming per DESIGN-SYSTEM.md.                             |
| Motion             | **Framer Motion**                         | CSS transitions only                                            | Needed for the micro-interaction differentiation strategy (see USER-EXPERIENCE.md) without hand-rolling animation logic.                                                                                                                  |
| State management   | **Zustand**                               | Redux, Context API                                              | Atomic, decoupled stores per domain (organizer/renamer/converter/history) without Redux boilerplate; well-suited to Electron apps with multiple semi-independent feature areas.                                                           |
| IPC                | **Context-isolated preload bridge**       | nodeIntegration: true                                           | Security requirement — never expose raw Node.js to renderer (see SYSTEM-ARCHITECTURE.md Security section).                                                                                                                                |
| Media conversion   | **FFmpeg** (child process)                | Direct native bindings (fluent-ffmpeg wrapper considered)       | Industry-standard engine (also what HandBrake wraps internally); direct child-process control gives full flag/preset flexibility without an abstraction layer masking capability.                                                         |
| Local persistence  | **SQLite (better-sqlite3) or JSON files** | IndexedDB (renderer-only, not accessible from main), full RDBMS | Lightweight, file-based, no server needed; SQLite preferred if undo-history queries grow complex, plain JSON acceptable for MVP settings/rule storage — final choice deferred to Task 01 implementation (see DATA-MODEL.md phasing note). |
| File watching      | **chokidar**                              | Node's native fs.watch                                          | Cross-platform consistency — native fs.watch behaves differently across Windows/macOS/Linux; chokidar normalizes this, which matters directly for Organizer's Auto Mode reliability.                                                      |
| Packaging          | **electron-builder**                      | electron-forge                                                  | Mature, widely used for producing signed macOS/Windows installers; matches existing `npm run build:mac` / `build:win` scripts already in place.                                                                                           |

## Platform Expansion Additions (adopted from `docs/PLATFORM-FEATURES-V2.md`)

The v2.0+ platform vision resolves the local-persistence open question and adds several architecture-level dependencies that are adopted **now**, at MVP time, because they are expensive to retrofit later even though the features they support ship in later phases.

| Layer                          | Chosen                                                                                                      | Why Adopted at MVP Time                                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local persistence              | **SQLite + Drizzle ORM** (resolves prior open question)                                                     | Search indexing, duplicate-detection hashes, tags, analytics, and multi-table history all need real relational/indexed queries — plain JSON would require a painful migration later. Drizzle gives type-safe schema/migrations matching the TypeScript-first stack.                                                                         |
| Concurrency for CPU-heavy work | **Node.js worker_threads**                                                                                  | Hashing (duplicate detection), thumbnail/preview generation, and search indexing are CPU-bound and must not share the main process event loop with IPC/file-watching — same principle already applied to FFmpeg (child process), extended to in-process CPU work.                                                                           |
| Background job scheduling      | **Persistent queue, BullMQ-inspired design adapted for a single-process desktop app (no Redis dependency)** | Needed for v2.1 Scheduled Tasks and Workflow Automation; must be designed once, not bolted on per-feature.                                                                                                                                                                                                                                  |
| Undo/redo & operation history  | **Command/event architecture** (formalizes MVP's simpler append-only `BatchRecord` log)                     | Supports v2.1 Workflow chaining and v2.0 File Version History without a rewrite of the MVP undo system — MVP implementation should already follow the command-object pattern even though full command chaining isn't exposed until v2.1.                                                                                                    |
| Plugin extensibility (v2.4)    | **Typed Plugin SDK with capability-based permissions**                                                      | Must be designed before any plugin marketplace UI work begins — a plugin with unchecked file-system/FFmpeg access would undo the IPC security model (see SYSTEM-ARCHITECTURE.md). Not built at MVP time, but the main-process module boundaries (see SYSTEM-ARCHITECTURE.md modular architecture) are shaped now to make it possible later. |

**Practical MVP impact**: implement local persistence directly in SQLite+Drizzle from Task 02 (`tasks/02-Architecture.md`) rather than JSON, even though MVP itself only needs `RuleSet`/`RenamePattern`/`ConversionPreset`/`BatchRecord`/`AppSettings`. This avoids a second, disruptive migration when v2.0 search/duplicate/tag features arrive.
