# 10-v2.2-AI-Organizer.md

Cross-reference: `docs/PLATFORM-FEATURES-V2.md` v2.2 section. **Read `docs/RISKS.md` Platform Expansion Risks before starting — AI features have explicit guardrails.**

## AI File Organizer

- [ ] Define classification categories (invoices, resumes, screenshots, receipts, projects, etc.) as a starting taxonomy, user-editable.
- [ ] Implement content inspection pipeline: filename, metadata, EXIF, OCR (for scanned docs/images), file content signals.
- [ ] Implement as a **suggestion layer**: AI proposes a destination/category, user reviews and approves before any move occurs — never auto-applies silently (mandatory guardrail per RISKS.md).
- [ ] Local-model-first evaluation (e.g., Ollama) vs. third-party API — decision must preserve local-first/privacy positioning (see `docs/INTEGRATIONS.md`).

## AI Smart Rename

- [ ] Content-aware filename generation using OCR/object detection/metadata.
- [ ] **Face recognition explicitly requires its own opt-in consent flow** (not bundled into a general "enable AI" toggle) — flagged as a distinct risk in RISKS.md given privacy sensitivity.
- [ ] Preview-before-commit for AI-generated names, same as MVP's rename preview pattern.

## AI Assistant

- [ ] Natural-language command interface routed through existing IPC contract (no new backend capability — the assistant translates intent into existing `fileflow.*` calls).
- [ ] Scope initial command set (organize folder X, find duplicates, compress videos, rename invoices) rather than open-ended freeform capability.

## File Tagging System

- [ ] Implement `Tag` / `FileTag` many-to-many schema (see `docs/DATA-MODEL.md`).
- [ ] Tag management UI (create/assign/filter by tag), independent of folder structure.
