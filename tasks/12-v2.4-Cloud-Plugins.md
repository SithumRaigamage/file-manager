# 12-v2.4-Cloud-Plugins.md

Cross-reference: `docs/PLATFORM-FEATURES-V2.md` v2.4 section. **This phase introduces FileFlow's first real network/cloud data-handling obligation — do not begin without the opt-in/privacy policy work below.**

## Cloud Integration

- [ ] Define explicit opt-in flow and data-handling/privacy policy **before** any implementation (see `docs/RISKS.md`, `docs/INTEGRATIONS.md`).
- [ ] Google Drive, Dropbox, OneDrive, iCloud, AWS S3, Backblaze connectors.
- [ ] Define which operations (organize/rename/convert) are supported against cloud-backed folders vs. local-only.

## Cross-Platform Sync

- [ ] Sync settings, rules, presets, themes, history across devices — depends on Cloud Integration or a dedicated sync backend.
- [ ] Conflict resolution strategy for sync (last-write-wins vs. merge) — decide and document explicitly.

## Plugin System / Marketplace

- [ ] Design capability-based permission model **before** any marketplace UI (see `docs/SYSTEM-ARCHITECTURE.md` Plugin Architecture) — plugin manifests declare exact required capabilities (filesystem:read, ffmpeg:invoke, network, etc.).
- [ ] Build Plugin SDK with typed APIs matching the existing `docs/API-CONTRACT.md` philosophy.
- [ ] Marketplace UI: discover/install/manage plugins.
- [ ] First-party reference plugins (OCR, image tools, cloud provider, compression) to validate the SDK before opening to third parties.

## Favorites & Workspaces

- [ ] `Workspace` entity (see `docs/DATA-MODEL.md`) — named, pinned folder collections.
- [ ] One-click workspace switching UI.

## Session Restore

- [ ] Persist and restore: open folders/tabs, active queue, undo/history scroll position on relaunch.
